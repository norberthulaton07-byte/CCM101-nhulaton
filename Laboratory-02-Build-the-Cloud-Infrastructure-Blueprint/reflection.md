## Mission Reflection

Honestly, out of all the cloud infrastructure components, I think networking is the most important one. Like, you can have the best compute or storage setup ever, but if there's no network connecting everything, none of it really matters because users can't even reach it. It's basically the thing that ties everything together.
Linux is a big deal in cloud computing too. A lot of cloud servers actually run on Linux because it's free and doesn't need expensive licenses like other operating systems. Using it directly in the Killercoda terminal made me understand why so many cloud engineers use it — it's simple once you get used to it, and it just works.
Technical documentation is also important before deploying anything because it keeps things organized. If you don't write stuff down, you're probably going to forget why you did something a certain way, especially if the project gets more complicated later on. It also just makes it easier for other people to understand what you did.
This activity taught me a bunch of new stuff I only really knew in theory before, like using Git and GitHub, working in the Linux terminal, editing files with nano, and writing in Markdown. I ran into a few errors along the way, but figuring them out actually helped me understand things better instead of just following instructions blindly.
My GitHub portfolio also looks a lot more legit now. Before, it was basically empty, but now I have an actual organized project with proper documentation, tables, diagrams, and folders that make sense. It's something I could actually show someone if I needed to.
